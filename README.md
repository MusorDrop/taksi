## 📖 О проекте

Проект призван решить проблему долгой и дорогой дороги студентов от центра города до удаленных кампусов (например, Новокольцовский). 
Платформа позволяет водителям публиковать маршруты, а пассажирам — быстро находить машину "по пути". 

**Ключевая фишка проекта** — интеграция с LLM (языковыми моделями) для «умного матчинга». Система понимает естественные запросы (например, *"Еду завтра в 8:30 от Уралмаша, могу взять двоих"*), автоматически находит пересечения маршрутов с учетом гибких окон по времени и рассчитывает справедливую цену.

## 💡 Бизнес-логика и механика платформы

### 🎯 1. Проблема и решение

- **Контекст проблемы:**
  Студенты Уральского федерального университета (УрФУ) ежедневно сталкиваются с транспортными сложностями при поездках между центром Екатеринбурга (корпуса на Мира, Ленина) и новым удаленным кампусом в **Новокольцовском**. Дорога на общественном транспорте может занимать до 2 часов с пересадками и переполненными автобусами, а регулярные поездки на коммерческом такси обходятся в 400–700+ ₽ в одну сторону, что создает существенную финансовую нагрузку на бюджет студентов.
- **Решение платформы «Попутка ИИ»:**
  Студенческий карпулинг (райдшеринг), объединяющий студентов-водителей и студентов-пассажиров, двигающихся по схожим маршрутам. 
  - **Для пассажиров:** быстрый, комфортный и безопасный способ добраться до кампуса или города по цене в разы ниже такси.
  - **Для водителей:** компенсация расходов на бензин и амортизацию автомобиля за счет попутчиков без необходимости работать в классическом такси.
  - **Для университета:** снижение нагрузки на общественный транспорт и сплочение студенческого комьюнити.

### 🧭 2. Алгоритм поиска и гео-матчинг (PostGIS Spatial Matching)

Поиск попутных маршрутов базируется на мощных возможностях гео-пространственного индексирования **PostGIS**:

1. **Запрос пассажира:**
   Пассажир указывает координаты точки отправления (`start_lat`, `start_lon`) и/или точки назначения (`end_lat`, `end_lon`), а также желаемый радиус поиска (`radius`, по умолчанию **1 000 метров**).
2. **Пространственная фильтрация (`ST_DWithin`):**
   Сервер выполняет высокопроизводительный гео-запрос, фильтрующий маршруты с использованием пространственного типа данных `geography` (учитывающего сферическую форму Земли по проекции WGS 84 / EPSG:4326):
   ```sql
   ST_DWithin(
     r.start_point::geography,
     ST_SetSRID(ST_MakePoint(search_lon, search_lat), 4326)::geography,
     radius_in_meters
   )
   ```
3. **Гибкий матчинг:**
   - Поиск по радиусу посадки (рядом с пассажиром);
   - Поиск по радиусу высадки (рядом с кампусом / нужным корпусом);
   - Комбинированный поиск (и старт, и финиш в пределах радиусов);
   - Фильтрация по временному окну (`departure_time`) и наличию свободных мест (`available_seats > 0`).

### 💰 3. Ценообразование и динамические тарифы

Система обеспечивает баланс между доступностью для пассажиров и справедливостью для водителей:

| Параметр | Условие / Значение | Описание |
|---|---|---|
| **Ручная цена** | По выбору водителя | Водитель при создании поездки может вручную указать фиксированную стоимость (`base_price`). |
| **Автоматический расчет** | Если цена не указана | Сервер рассчитывает дистанцию и стоимость по кривизне Земли через PostGIS. |
| **Расчет дистанции** | `ST_DistanceSphere` | Точное вычисление расстояния по сфере Земли между точкой старта и финиша в км (`distance_km`). |
| **Базовый тариф** | **6 ₽ за 1 км** | Справедливая ставка, окупающая расходы на топливо для стандартного городского маршрута. |
| **Пиковый коэффициент** | **x1.3** | Повышающий множитель в часы наибольшей загруженности дорог и максимального спроса. |

#### ⏰ Часы пик (Asia/Yekaterinburg, UTC+5):
- 🌅 **Утренний пик:** `07:30 – 09:30` (активный выезд на первую и вторую пары в кампус);
- 🌇 **Вечерний пик:** `17:00 – 19:00` (возвращение студентов из кампуса и окончание учебного дня).

#### 🧮 Формула расчета:
$$\text{Цена поездки} = \text{Дистанция (км)} \times 6 \times (\text{1.3 в часы пик или 1.0 в стандартное время})$$

*Пример:* Маршрут от Главного учебного корпуса (Мира, 19) до Кампуса Новокольцовский (~14 км):
- *В обычные часы:* $14 \times 6 = 84\text{ ₽}$
- *В утренний пик (08:00):* $14 \times 6 \times 1.3 \approx 109\text{ ₽}$ (в 4–6 раз дешевле агрегаторов такси).

#### 👥 Динамическое разделение стоимости (Split Fare)
Для максимальной выгоды студентов в платформе работает динамическая модель совместной оплаты:
- Общая стоимость маршрута (`price`) делится поровну между всеми подтвержденными пассажирами (`passenger_ids`).
- Чем больше попутчиков присоединяется к поездке, тем выгоднее поездка для каждого пассажира:
  $$\text{current\_price} = \left\lceil \frac{\text{price}}{\max(\text{число пассажиров}, 1)} \right\rceil$$
- Пересчет происходит мгновенно и динамически при бронировании места (`POST /api/rides/:id/join`) или отмене участия (`POST /api/rides/:id/leave`).
- **100% на базе данных:** моковые и фейковые данные полностью вырезаны как на бэкенде, так и на фронтенде — вся система функционирует строго на основе реальных данных из PostgreSQL.

### 🚗 4. Гараж автомобилей водителя (Vehicle Fleet)

Для максимального комфорта и безопасности поездок водители ведут персональный реестр своих автомобилей:
- 🚘 **Управление автомобилями:** водитель регистрирует свои транспортные средства (`POST /api/vehicles`, `GET /api/vehicles`) с указанием марки и модели, цвета и госномера. Все данные автоматически очищаются и приводятся к стандартизированному формату.
- 🔗 **Привязка машины к поездке:** при создании маршрута водитель выбирает авто из личного гаража (`vehicle_id`), что фиксируется сервером после строгой проверки прав владения.
- 👀 **Прозрачность для пассажиров:** данные об автомобиле (марка, цвет, госномер) автоматически включаются в карточку поездки, благодаря чему студенты безошибочно находят нужную машину на остановках или парковках кампуса.

### 🛡️ 5. Система доверия, безопасности и репутации

Доверие внутри университетской среды — фундаментальный фактор платформы «Попутка ИИ»:

- 🌟 **Двусторонняя система рейтингов и отзывов:**
  После каждой завершенной поездки пассажиры и водители обмениваются оценками (от 1 до 5 звезд) и текстовыми отзывами (`POST /api/reviews`). Средний рейтинг пользователя рассчитывается автоматически в режиме реального времени (`users.rating`) и выводится в профиле (`GET /api/auth/me`) и поисковой выдаче. Реализована строгая защита от накруток (запрет оценки самого себя, проверка привязки к поездке).
- 🔒 **Надежность бронирования:**
  Защита от овербукинга и гонок запросов (race conditions) при одновременном бронировании мест с помощью транзакций PostgreSQL с блокировкой строк (`SELECT ... FOR UPDATE`).
- 👥 **Предпочтения и профили:**
  Возможность указать важные детали поездки: курение, прослушивание музыки, готовность к беседе, наличие багажа и контакт для экстренной связи.

## 📌 Текущий статус и возможности проекта

Продукт находится в высокой степени готовности для демонстрации и защиты:

- 🟢 **Базовые сервисы и API:** серверная архитектура на Express + PostgreSQL/PostGIS, регистрация и авторизация по логину на JWT/bcryptjs (без почты), профиль пользователя (`GET /api/auth/me`), публикация поездок водителями, просмотр доступных маршрутов и атомарное бронирование мест с защитой от race conditions.
- 📍 **Гео-поиск и ценообразование:** ядро пространственной фильтрации и расчета стоимости. Реализован гео-поиск поездок через PostGIS `ST_DWithin` в заданном радиусе, точный расчет расстояния через `ST_DistanceSphere`, базовый тариф 6 руб/км и пиковый коэффициент x1.3 в часы пик (07:30-09:30 и 17:00-19:00).
- 🚗 **Гараж автомобилей (Vehicles):** регистрация личных авто водителя (`POST /api/vehicles`, `GET /api/vehicles`), надежная привязка машины к поездке (`vehicle_id`) и отображение характеристик авто пассажирам.
- ⭐ **Система рейтингов и отзывов:** двустороннее оценивание поездок (`POST /api/reviews`, `GET /api/reviews`), автоматический пересчет рейтинга пользователя в режиме реального времени, защита от накруток.
- 🛡 **Комплексная безопасность:** интегрированы `helmet` (защитные HTTP-заголовки), `express-rate-limit` (защита от брутфорса и перегрузки), `cors`, централизованная валидация входных данных и аутентификация через middleware.
- 🧪 **Автоматизированное тестирование:** комплекс из 9 сквозных smoke-тестов API (`npm test` в папке `backend`), валидирующий 100% критических сценариев (авторизация, бронирование, динамические цены, PostGIS, отзывы/рейтинг и гараж авто).
- 💳 **Динамическое разделение стоимости (Split Fare) и 100% работа на БД:** реализован алгоритм честного деления общей стоимости (`price`) между подтвержденными пассажирами (`current_price`), динамически обновляющийся в реальном времени при бронировании мест. Моковые данные полностью вырезаны — система оперирует исключительно живыми записями PostgreSQL.

### 🔹 [Backend](./backend/README.md)
Сердце системы, обрабатывающее логику, работу с гео-данными и ИИ.
- **Движок:** Node.js + Express.js v5.
- **База данных:** PostgreSQL + PostGIS (пространственные индексы, гео-запросы `ST_DWithin`, расчет дистанции `ST_DistanceSphere`).
- **Алгоритмы ядра:** Динамическое ценообразование (базовый тариф 6 руб/км, коэффициент x1.3 в часы пик) и PostGIS-матчинг по радиусу.
- **Модули сервиса:** Управление поездками, гараж автомобилей водителя (`/api/vehicles`), система рейтингов и отзывов (`/api/reviews`).
- **Безопасность и авторизация:** JWT, bcryptjs, Helmet, Rate Limiter, CORS.
- **Взаимодействие:** REST API с автоматическими smoke-тестами (100% pass).

### 🔹 [Frontend](./frontend/README.md)
Клиентское PWA-приложение, удобное для использования со смартфонов.

## 🚀 Быстрый старт (Локальный запуск)

Для комфортной работы вам понадобятся: **Node.js (v20+)** и **PostgreSQL с расширением PostGIS**.

### 1. Запуск Backend-сервера
В первом окне терминала запустите серверную часть:
```cmd
# Перейдите в директорию бэкенда
cd backend

# Установите зависимости
npm install

# Создайте файл .env с настройками БД и JWT (см. backend/README.md)
# Запустите сервер (по умолчанию порт 3000)
npm start

# Для запуска smoke-тестов
npm test
```

### 2. Запуск Frontend-клиента
Не закрывая терминал бэкенда, откройте **новую вкладку/окно** терминала:
```cmd
# Перейдите в директорию фронтенда
cd frontend

# Установите зависимости
npm install

# Запустите dev-сервер Vite (с Hot-Reload)
npm run dev
```
> После успешного запуска терминал выдаст ссылку (обычно `http://localhost:5173`), по которой доступен интерфейс.

## 🛠 Правила работы с Git (Git Flow)

Чтобы команда не блокировала друг друга, мы придерживаемся строгих правил слияния веток.

- `main` — **Продакшен**. Строго для рабочих и протестированных релизов. Прямые коммиты запрещены.
- `dev` — **Интеграционная ветка**. Главная рабочая ветка, куда стекается весь новый код.
- `feat/*`, `bugfix/*` — **Ветки разработчиков**. (Например, `feat/backend`, `frontend`).

### Как вносить изменения:
1. Заберите актуальный `dev`: `git checkout dev && git pull`.
2. Создайте свою рабочую ветку: `git checkout -b feat/my-new-feature`.
3. Пишите код, делайте коммиты (в папках `frontend/` или `backend/`).
4. Отправьте ветку на GitHub: `git push origin feat/my-new-feature`.
5. Создайте **Pull Request** на слияние вашей ветки с веткой `dev`.
6. После ревью (проверки) код вливается в `dev`, а затем мы совместно выкатываем его в `main`.
