## 📖 О проекте

Проект призван решить проблему долгой и дорогой дороги студентов от центра города до удаленных кампусов (например, Новокольцовский). 
Платформа позволяет водителям публиковать маршруты, а пассажирам — быстро находить машину "по пути". 

**Ключевая фишка проекта** — интеграция с LLM (языковыми моделями) для «умного матчинга». Система понимает естественные запросы (например, *"Еду завтра в 8:30 от Уралмаша, могу взять двоих"*), автоматически находит пересечения маршрутов с учетом гибких окон по времени и рассчитывает справедливую цену.

## 💡 Бизнес-логика и механика платформы

### 🎯 1. Проблема и решение

- **Контекст проблемы:**
  Студенты Уральского федерального университета (УрФУ) ежедневно сталкиваются с транспортными сложностями при поездках между центром Екатеринбурга (корпуса на Мира, Ленина) и новым удаленным кампусом в **Новокольцовском**. Дорога на общественном транспорте может занимать до 2 часов с пересадками и переполненными автобусами, а регулярные поездки на коммерческом такси обходятся в 400–700+ ₽ в одну сторону, что создает существенную финансовую нагрузку на бюджет студентов.
- **Решение платформы «Попутка ИИ»:**
  Студенческий карпулинг (райдшеринг), объединяющий студентов-водителей и студентов-пассажиров, двигающихся по схожим маршрутам. 
  - **Для пассажиров:** быстрый, комфортный и безопасный способ добраться до кампуса или города по цене в разы ниже такси.
  - **Для водителей:** компенсация расходов на бензин и амортизацию автомобиля за счет попутчиков без необходимости работать в классическом такси.
  - **Для университета:** снижение нагрузки на общественный транспорт и сплочение студенческого комьюнити.

### 🧭 2. Алгоритм поиска и гео-матчинг (PostGIS Spatial Matching)

Поиск попутных маршрутов базируется на мощных возможностях гео-пространственного индексирования **PostGIS**:

1. **Запрос пассажира:**
   Пассажир указывает координаты точки отправления (`start_lat`, `start_lon`) и/или точки назначения (`end_lat`, `end_lon`), а также желаемый радиус поиска (`radius`, по умолчанию **1 000 метров**).
2. **Пространственная фильтрация (`ST_DWithin`):**
   Сервер выполняет высокопроизводительный гео-запрос, фильтрующий маршруты с использованием пространственного типа данных `geography` (учитывающего сферическую форму Земли по проекции WGS 84 / EPSG:4326):
   ```sql
   ST_DWithin(
     r.start_point::geography,
     ST_SetSRID(ST_MakePoint(search_lon, search_lat), 4326)::geography,
     radius_in_meters
   )
   ```
3. **Гибкий матчинг:**
   - Поиск по радиусу посадки (рядом с пассажиром);
   - Поиск по радиусу высадки (рядом с кампусом / нужным корпусом);
   - Комбинированный поиск (и старт, и финиш в пределах радиусов);
   - Фильтрация по временному окну (`departure_time`) и наличию свободных мест (`available_seats > 0`).

### 💰 3. Ценообразование: Фиксированная цена за место (Отмена Split Fare)

Для прозрачности и финансовой предсказуемости студентов произведен **полный отказ от динамической модели Split Fare** (когда цена делилась на число пассажиров и менялась). Теперь действует понятная и прозрачная **фиксированная стоимость за 1 посадочное место**:

| Параметр | Условие / Значение | Описание |
|---|---|---|
| **Ручная цена** | По выбору водителя | Водитель при создании поездки вручную задает фиксированную цену за 1 место (`base_price`). |
| **Автоматический расчет** | Если цена не указана | Сервер рассчитывает дистанцию и стоимость по кривизне Земли через PostGIS. |
| **Расчет дистанции** | `ST_DistanceSphere` | Точное вычисление расстояния по сфере Земли между точкой старта и финиша в км (`distance_km`). |
| **Базовый тариф** | **6 ₽ за 1 км** | Справедливая ставка, окупающая расходы на топливо для стандартного городского маршрута. |
| **Пиковый коэффициент** | **x1.3** | Повышающий множитель в часы наибольшей загруженности дорог и максимального спроса. |
| **Итоговая цена для пассажира** | `current_price = base_price` | Строго фиксированная ставка за каждое посадочное место. |

#### ⏰ Часы пик (Asia/Yekaterinburg, UTC+5):
- 🌅 **Утренний пик:** `07:30 – 09:30` (выезд на первую и вторую пары в кампус);
- 🌇 **Вечерний пик:** `17:00 – 19:00` (возвращение студентов из кампуса в город).

#### 🧮 Формула автоматического расчета:
$$\text{Цена за 1 место} = \text{Дистанция (км)} \times 6 \times (\text{1.3 в часы пик или 1.0 в стандартное время})$$

*Пример:* Маршрут от Главного учебного корпуса (Мира, 19) до Кампуса Новокольцовский (~14 км):
- *В обычные часы:* $14 \times 6 = 84\text{ ₽}$ за посадочное место;
- *В утренний пик (08:00):* $14 \times 6 \times 1.3 \approx 109\text{ ₽}$ за место (в 4–6 раз дешевле агрегаторов такси).

### 🚗 4. Гараж автомобилей: Количество мест и редактирование авто

Личный автопарк водителя защищает сервис от недобросовестных объявлений и повышает прозрачность:
- 💺 **Указание количества мест (`seats`):** при добавлении автомобиля водитель указывает количество свободных посадочных мест (от 1 до 8, по умолчанию 4). Это значение автоматически подставляется при создании поездки с этим автомобилем.
- ✏️ **Редактирование автомобиля в гараже:** водитель может в любой момент изменить данные своего автомобиля (`PATCH /api/vehicles/:id`): марку, госномер, цвет и число мест.
- 🚫 **Блокировка создания маршрутов без авто:** водитель физически не может опубликовать поездку, если в его гараже нет ни одной машины. Интерфейс блокирует форму и предлагает перейти в профиль для добавления авто.
- 👀 **Прозрачность для пассажиров:** данные об автомобиле (марка, цвет, госномер) автоматически отображаются в карточке поездки.

---

### 📅 5. Форматы поездок: Одноразовые и Регулярные маршруты

Сервис гибко подстраивается под график учебы студентов:
- 📆 **Одноразовые поездки (`one_off`):** классический формат с указанием точной календарной даты (`YYYY-MM-DD`) и времени отправления.
- 🔄 **Регулярные поездки (`regular`):** поездки с расписанием по фиксированным дням недели (например, `Пн, Вт, Ср, Чт, Пт`). Удобно для постоянных поездок на пары без ежедневного создания новых поездок.
- 🗓 **Выбор дня пассажиром при бронировании:** при присоединении к регулярной поездке пассажир может выбрать конкретный день (Пн, Ср и т.д.), в который планирует ехать. Выбранный день сохраняется в бронировании и виден водителю в карточке маршрута.
- 🏷 **Визуальные бейджи:** в ленте поиска регулярные поездки визуально выделяются меткой с днями недели.

---

### 👤 6. Профиль пользователя и верификация контактов

- 📞 **Обязательный телефон при регистрации:** поле `phone` является строго обязательным при создании аккаунта (`POST /api/auth/register`), что исключает спам и обеспечивает возможность экстренной связи.
- ✏️ **Редактирование телефона и Telegram:** пользователь может легко обновить свои контактные данные (номер телефона и username в Telegram) в профиле (`PATCH /api/auth/me`).
- 🖼 **Аватарки:** загрузка и обновление фото профиля с проверкой типов файлов (`POST /api/auth/me/avatar`).

---

### 👥 7. Управление поездкой и прямая связь

- 📋 **Список пассажиров для водителя:** водитель в карточке своего маршрута видит полный список подтвержденных пассажиров с их именами, аватарками, телефонами и ссылками на Telegram.
- 🚫 **Исключение пассажиров водителем:** водитель может исключить любого пассажира из поездки (`DELETE /api/rides/:id/passengers/:passengerId`). При этом бронирование удаляется, а количество свободных мест автоматически возвращается (`available_seats + 1`).
- ✏️ **Редактирование активного маршрута:** водитель может изменить параметры созданной поездки (`PATCH /api/rides/:id`): пункты отправления и назначения, время выезда, стоимость за место, число мест, автомобиль и тип поездки.
- 📞 **Звонки водителю напрямую:** в карточке поездки пассажирам доступна кнопка **«Позвонить»** (прямой вызов через системную ссылку `tel:...`), а также кнопка перехода в чат Telegram.

---

### 🛡️ 8. Система доверия, безопасности и репутации

- 🌟 **Двусторонняя система рейтингов и отзывов:** после поездки пассажиры и водители оставляют отзывы и оценки от 1 до 5 звезд (`POST /api/reviews`). Рейтинг пересчитывается мгновенно в реальном времени.
- 🔒 **Надежность бронирования:** защита от овербукинга и гонок запросов (race conditions) через транзакции PostgreSQL с блокировкой строк (`SELECT ... FOR UPDATE`).
- 👥 **Предпочтения:** детали поездки (курение, музыка, разговорчивость, багаж).

Продукт полностью готов к демонстрации и защите:

- 📍 **Гео-поиск и ценообразование:** пространственный поиск PostGIS `ST_DWithin` в радиусе, точный расчет расстояния через `ST_DistanceSphere`, базовый тариф 6 руб/км и пиковый коэффициент x1.3.

- 🚗 **Гараж автомобилей:** учет посадочных мест (1–8), редактирование авто (`PATCH /api/vehicles/:id`), блокировка создания поездок без зарегистрированного автомобиля.
- 📅 **Типы поездок:** разовые (по дате) и регулярные (по дням недели: Пн-Вс) с возможностью выбора конкретного дня (Пн, Ср и т.д.) пассажиром при присоединении к поездке.
- 👥 **Управление и прямая связь:** водитель просматривает список пассажиров, может исключать их из поездки и редактировать маршрут. Пассажиры могут совершать прямые звонки водителю (`tel:`) и писать в Telegram.
- ⭐ **Система рейтингов и отзывов:** двусторонние отзывы (`POST /api/reviews`), автоматический пересчет рейтинга пользователя.
- 🛡 **Комплексная безопасность:** Helmet, Rate Limiter, CORS, валидация данных, транзакции с блокировками строк.
- 🧪 **Автоматизированное тестирование:** набор сквозных smoke-тестов API (`npm test` в папке `backend`).
- 📊 **Админ-панель:** панель управления с аналитикой, списком пользователей, блокировкой и аудитом поездок.

│   └── README.md             # Специфичная документация по UI

### 🔹 [Backend](./backend/README.md)
Сердце системы, обрабатывающее логику, гео-данные и API платформы.
- **Движок:** Node.js + Express.js v5.
- **База данных:** PostgreSQL + PostGIS (гео-индексы, фильтрация `ST_DWithin`, расчет расстояний `ST_DistanceSphere`).
- **Экономика:** Фиксированная цена за 1 место (отмена Split Fare), расчет пикового тарифа (x1.3 в часы пик).
- **Модули сервиса:**
  - Управление поездками (одноразовые по дате и регулярные по дням недели с выбором дня пассажиром, блокировка создания без авто);
  - Управление пассажирами (список пассажиров, исключение водителем `DELETE /api/rides/:id/passengers/:passengerId`);
  - Редактирование маршрута водителя (`PATCH /api/rides/:id`);
  - Гараж авто с учетом количества мест (`seats`) и редактированием (`PATCH /api/vehicles/:id`);
  - Профиль с обязательным телефоном при регистрации и редактированием контактов (`PATCH /api/auth/me`);
  - Двусторонняя система рейтингов и отзывов (`/api/reviews`).
- **Безопасность:** JWT, bcryptjs, Helmet, Rate Limiter, CORS, транзакции PostgreSQL с блокировкой строк (`FOR UPDATE`).
- **Тестирование:** Сквозные автоматические smoke-тесты API.

### 🔹 [Frontend](./frontend/README.md)
Клиентское адаптивное SPA/PWA-приложение для смартфонов и ПК.
- **Движок:** React 19 + Vite.
- **Язык & UI:** TypeScript, Material UI (MUI v6) с поддержкой светлой и темной тем.
- **Функционал:**
  - Интерактивный поиск поездок с фильтрацией и отображением маршрута на карте (Leaflet);
  - Создание поездок с выбором типа (одноразовая / регулярная) и AI-рекомендацией тарифа;
  - Блокировка создания маршрутов при отсутствии автомобилей с подсказкой перейти в профиль;
  - Детальные карточки поездок с прямым звонком водителю (`tel:`), кнопкой Telegram и списком пассажиров;
  - Инструменты водителя: исключение пассажиров и быстрое редактирование маршрута;
  - Профиль: редактирование номера телефона и Telegram, загрузка аватара, гараж авто с формой редактирования.

## 🚀 Быстрый старт (Локальный запуск)

Для комфортной работы вам понадобятся: **Node.js (v20+)** и **PostgreSQL с расширением PostGIS**.

### 1. Запуск Backend-сервера
В первом окне терминала запустите серверную часть:
```cmd
# Перейдите в директорию бэкенда
cd backend

# Установите зависимости
npm install

# Создайте файл .env с настройками БД и JWT (см. backend/README.md)
# Запустите сервер (по умолчанию порт 3000)
npm start

# Для запуска smoke-тестов
npm test
```

### 2. Запуск Frontend-клиента
Не закрывая терминал бэкенда, откройте **новую вкладку/окно** терминала:
```cmd
# Перейдите в директорию фронтенда
cd frontend

# Установите зависимости
npm install

# Запустите dev-сервер Vite (с Hot-Reload)
npm run dev
```
> После успешного запуска терминал выдаст ссылку (обычно `http://localhost:5173`), по которой доступен интерфейс.

## 🛠 Правила работы с Git (Git Flow)

Чтобы команда не блокировала друг друга, мы придерживаемся строгих правил слияния веток.

- `main` — **Продакшен**. Строго для рабочих и протестированных релизов. Прямые коммиты запрещены.
- `dev` — **Интеграционная ветка**. Главная рабочая ветка, куда стекается весь новый код.
- `feat/*`, `bugfix/*` — **Ветки разработчиков**. (Например, `feat/backend`, `frontend`).

### Как вносить изменения:
1. Заберите актуальный `dev`: `git checkout dev && git pull`.
2. Создайте свою рабочую ветку: `git checkout -b feat/my-new-feature`.
3. Пишите код, делайте коммиты (в папках `frontend/` или `backend/`).
4. Отправьте ветку на GitHub: `git push origin feat/my-new-feature`.
5. Создайте **Pull Request** на слияние вашей ветки с веткой `dev`.
6. После ревью (проверки) код вливается в `dev`, а затем мы совместно выкатываем его в `main`.
