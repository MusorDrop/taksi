# План разработки Бэкенда (Попутка ИИ)

## Этап 1: Базовая инфраструктура (Скелет)
- [x] Инициализация проекта (package.json).
- [x] Установка зависимостей (Express, pg, cors, dotenv).
- [x] Настройка подключения к базе данных PostgreSQL (PostGIS).
- [x] Базовая структура (routes, controllers, db).

## Этап 2: Базовое "Решение" (CRUD и Авторизация)
- [x] `POST /api/auth/login` — Авторизация/Регистрация (username, password).
- [x] `POST /api/rides` — Публикация маршрута водителем.
- [x] `GET /api/rides` — Базовое получение списка поездок (пока без сложных гео-фильтров).
- [x] `POST /api/rides/:id/join` — Присоединение пассажира к поездке (создание Match).
- [x] `POST /api/rides/:id/leave` — Отмена участия пассажира.

## Этап 3: Алгоритмы ядра (PostGIS и Математика)
*Согласно "Решению", ИИ для этого пока не нужен — используем PostGIS и простые алгоритмы.*
- [x] Внедрение гео-матчинга (PostGIS `ST_DWithin`) в `GET /api/rides`: поиск пересечений маршрутов пассажира и водителя с учетом радиуса и времени.
- [x] Базовый расчет расстояния поездки (`distanceKm`).
- [x] Базовое динамическое ценообразование и выявление пиковых часов (`isPeak`) на основе математики и времени.

## Этап 4: Рейтинги и Отзывы
- [x] `POST /api/reviews` — Создание отзыва о водителе или пассажире после поездки.
- [x] Интеграция рейтингов — Автоматический пересчет среднего рейтинга пользователя в его профиле.

## Этап 5: Автомобили (Vehicles)
- [ ] `POST /api/vehicles` — Добавление автомобиля в профиль водителя (марка, цвет, госномер).
- [ ] `GET /api/vehicles` — Получение списка автомобилей пользователя.
- [ ] Обновление `POST /api/rides` — Привязка конкретного автомобиля к создаваемой поездке.
