# План разработки платформы «Попутка ИИ»

Дорожная карта реализации и статус готовности модулей к защите проекта.

---

## 🟢 Реализованные этапы (Готово к защите)

### Этап 1: Базовая инфраструктура и архитектура (Скелет)
- [x] Инициализация проекта и конфигурация окружения (`package.json`, `.env`).
- [x] Подключение к реляционной СУБД **PostgreSQL** с гео-пространственным расширением **PostGIS**.
- [x] Модульная архитектура: маршрутизация Express, контроллеры, валидация входных данных, централизованный пул соединений `pg.Pool`.
- [x] Базовый health-check эндпоинт (`GET /api/health`) с проверкой статуса БД и PostGIS.

### Этап 2: Безопасность, Авторизация и Базовый CRUD поездок
- [x] Регистрация и аутентификация по логину и паролю без email (`POST /api/auth/register`, `POST /api/auth/login`).
- [x] Хеширование паролей через `bcryptjs` (10 раундов соли), генерация и проверка токенов JWT.
- [x] Эндпоинт профиля текущего пользователя (`GET /api/auth/me`).
- [x] Комплексная защита: `helmet` (безопасные HTTP-заголовки), `express-rate-limit` (защита от брутфорса и DoS), `cors`.
- [x] Публикация маршрута водителем (`POST /api/rides`) и получение списка поездок (`GET /api/rides`).
- [x] Атомарное бронирование мест пассажиром (`POST /api/rides/:id/join`) и отмена (`POST /api/rides/:id/leave`) с защитой от race conditions через транзакции PostgreSQL (`SELECT ... FOR UPDATE`).

### Этап 3: Алгоритмы ядра (PostGIS Spatial Matching и динамическое ценообразование)
- [x] Гео-пространственный поиск через PostGIS (`ST_DWithin`) в заданном радиусе (по умолчанию 1 000 м) вокруг точек посадки и высадки.
- [x] Высокоточный расчет дистанции маршрута по сфере Земли через `ST_DistanceSphere` (`distance_km`).
- [x] Динамическое ценообразование: базовый тариф **6 руб/км**, автоматический расчет стоимости поездки при публикации.
- [x] Алгоритм определения часов пик (07:30–09:30 и 17:00–19:00 по часовому поясу Екатеринбурга UTC+5) с повышающим коэффициентом **x1.3**.

### Этап 4: Система рейтингов и отзывов (Reviews & Reputation)
- [x] `POST /api/reviews` — создание двустороннего отзыва о водителе или пассажире после завершения поездки (оценка 1–5 звезд, текстовый комментарий).
- [x] `GET /api/reviews` — получение списка отзывов с гибкой фильтрацией по пользователю (`user_id`) или поездке (`ride_id`).
- [x] Автоматический пересчет и обновление среднего рейтинга пользователя (`rating`) в базе данных в реальном времени.
- [x] Защита от накруток: строгая валидация UUID, запрет оценки самого себя, проверка реального участия в поездке.
- [x] Отображение рейтинга водителя в профиле (`GET /api/auth/me`) и в карточках поездок (`GET /api/rides`).

### Этап 5: Гараж автомобилей (Vehicles Management)
- [x] `POST /api/vehicles` — добавление автомобиля в личный гараж водителя (марка/модель, цвет, госномер с автоматической санитизацией).
- [x] `GET /api/vehicles` — получение полного списка автомобилей текущего водителя.
- [x] Привязка конкретного автомобиля к создаваемой поездке (`POST /api/rides` с передачей `vehicle_id`).
- [x] Проверка владения автомобилем (водитель может привязать только автомобиль из своего гаража).
- [x] Интеграция данных об автомобиле в детали поездки для пассажиров (узнаваемость машины на парковках кампуса).
- [x] 100% покрытие автоматизированными smoke-тестами (`npm test` — 9 сквозных тестов).

## 🟡 Запланированные этапы (Дорожная карта к защите)

### Этап 6: Интеграция Фронтенда (Веб-версия, мобильный вид, подключение к API)
- [ ] **Адаптивный интерфейс (Mobile-first PWA):** разработка веб-клиента на React + Vite + TypeScript, оптимизированного под экраны смартфонов студентов.
- [ ] **Подключение к REST API бэкенда:** единый HTTP-клиент с обработкой JWT-токенов, авто-обновлением сессии и индикацией загрузки/ошибок.
- [ ] **Экран поиска поездок:** интерактивная форма гео-поиска (выбор точек на карте/списка локаций УрФУ, радиус, время) с выводом списка доступных карточек.
- [ ] **Личный кабинет и гараж водителя:** интерфейс управления автомобилями (добавление авто, просмотр гаража) и отображение истории поездок.
- [ ] **Форма публикации поездки:** выбор маршрута, даты, времени, свободных мест, привязка машины из гаража и динамический расчет стоимости.
- [ ] **Профиль и репутация:** экран профиля с отображением рейтинга со звездами, списком отзывов и пользовательскими предпочтениями (курение, музыка, багаж).

### Этап 7: Split Fare (Разделение стоимости) — деление цены между пассажирами
- [ ] **Алгоритм динамического шеринга расходов:** равномерное распределение базовой стоимости поездки между фактически забронировавшими места пассажирами:
  $$\text{Стоимость для пассажира} = \frac{\text{Общая стоимость поездки}}{\text{Количество пассажиров в машине}}$$
- [ ] **Экономика для студентов:** наглядная выгода — чем больше попутчиков присоединяется к машине, тем дешевле поездка для каждого участника.
- [ ] **Автоматический пересчет `agreed_price`:** перерасчет финальной цены в таблице `matches` в реальном времени при каждом новом бронировании (`/join`) или отмене (`/leave`).
- [ ] **Калькулятор стоимости:** предварительный расчет цены для пассажира до подтверждения бронирования с визуализацией шкалы экономии.
- [ ] **Уведомления об удешевлении:** передача обновленной цены пассажирам при присоединении новых попутчиков.

### Этап 8: Умный поиск через LLM (парсер текста "еду в 8:30 от Уралмаша")
- [ ] **Интеграция с API языковой модели:** подключение LLM (Google Gemini / OpenAI) для семантической обработки пользовательских запросов.
- [ ] **Парсинг естественной речи:** трансформация неструктурированного текста на русском языке (например, *"еду в 8:30 от Уралмаша"*, *"завтра к первой паре в Новокольцовский"*, *"в пятницу в 18:00 из центра до Мира"*) в строгий структурированный JSON.
- [ ] **Извлечение ключевых сущностей:** автоматическое определение геолокаций старта и финиша, даты, временного окна и требуемого числа мест.
- [ ] **Эндпоинт `POST /api/rides/ai-search`:** сквозная обработка запроса — промптинг LLM -> валидация JSON -> выполнение PostGIS `ST_DWithin` гео-поиска в базе данных.
- [ ] **Отказоустойчивость и Fallback:** автоматический возврат к стандартным координатам известных точек студенческого городка при неполных запросах.
